# Engine → Web contract (v1)

```python
from bsa.engine import analyze_file, PasswordRequired, UnsupportedFile
report: dict = analyze_file(path, password=None, applicant_name=None, original_filename=None)
```
- `PasswordRequired` → PDF is encrypted and no/wrong password given (UI must ask for password).
- `UnsupportedFile` → not a PDF/XLS/XLSX/CSV, or no transactions could be read (message in `str(e)`).
- Report is plain JSON-serialisable (dates are ISO strings `YYYY-MM-DD`, amounts are floats in INR).

## Top-level keys
| key | type | notes |
|---|---|---|
| `meta` | obj | `file_name, file_type (pdf/xlsx/csv), pages, bank_code, bank_name, bank_method, bank_certification {certified, samples, tool_edited_samples}, account_holder, account_number, ifsc, period_from, period_to (as printed in the header), months_covered (float; first to last row when truncated), truncated (null, or `{rows, rows_end, header_period_to}` when the bank export stopped at a row cap - 500/999/1000/2000/5000 rows with the last row >3 days before the header period end; EOD/ABB/monthly/averages then run to `rows_end`), txn_count, parse_method, parse_confidence (0-100), engine_version, analyzed_at` |
| `authenticity` | obj | `verdict`: `ORIGINAL` \| `SUSPICIOUS` \| `FAKE` \| `CANNOT_VERIFY` (spreadsheets only); `fake_reasons`: list[str] (why FAKE: third-party tool in producer/creator/author/XMP, garbled metadata, scanned, overlays, created before last txn); `score` 0-100; `checks`: list of `{name, status: pass\|warn\|fail\|info, detail}`; `pdf_metadata`: `{producer, creator, author, created, modified, encrypted, signed, eof_markers}`; `revisions`: null for a file saved once, else the file history `{revisions: [{n, date, bytes, producer, creator, signature, pages}], changes: [{from, to, minutes, comparable, signature, pages_changed, edits: [{page, y, before, after}] (first 60), lines_changed (= number of edits), fonts_added, tool_hint, annots_added, pages_added, pages_removed}], text_changed, uncomparable, linearized}` - each later incremental save is diffed against the version before it (bytes up to its %%EOF); page text changed => check 'Edited after generation' fail (FAKE with a new font / editor tool / page count change / other producer / >10 min or undated; else SUSPICIOUS). Scanned / unreadable PDFs return a verify-only report (`meta.verify_only = true`, empty analytics). Check names added 2026-11-23: 'Hidden text' (fail: white box painted over existing text), 'Generator vs bank' (warn: developer PDF library never seen on that certified bank's genuine statements), 'Generator mismatch' (fail: written by ReportLab, metadata names another report engine), 'Bank statement' (warn / info: verify-only file with no bank detected); a library re-save (MuPDF / qpdf / pypdf marks in the file bytes) shows inside 'Producer / creator / author' as "file contains traces of ...". Damaged files (0 pages, broken page tree, image codec in page content, decompression bomb) raise `UnsupportedFile` before any analysis. The web app runs the engine through `bsa.engine.isolated.analyze_isolated` (own process, `BSA_ANALYZE_TIMEOUT` s, default 120 -> HTTP 422 `analysis_timeout`). |
| `reconciliation` | obj | `status`: `MATCHED` \| `PARTIAL` \| `MISMATCH` \| `UNVERIFIED`; `opening_balance, closing_balance, total_credits, total_debits, computed_closing, closing_match (bool), rows_total, rows_verified, rows_mismatch, verified_pct`; `mismatch_rows`: list `{idx, date, narration, amount, balance, expected_balance}`; `printed_summary`: obj or null; `printed_summary_match`: bool or null; `name_match`: `{applicant, holder, status: MATCH\|PARTIAL\|MISMATCH\|NOT_CHECKED, score}` |
| `summary` | obj | underwriting facts only (no FOIR / eligibility - the underwriter computes those): `monthly_income (null when no salary), income_source (salary/none; old reports: avg_credits), avg_monthly_credits, avg_monthly_debits, abb, min_eod_balance, max_eod_balance, existing_emi (fixed EMIs only), short_term_repayment, bounce_count, distinct_lenders, salary_detected, low_balance_days_pct, cash_deposit_pct` |
| `salary` | obj | `detected (bool), confidence (0-100), employer, avg_amount, usual_day, months: [{month 'YYYY-MM', amount, date, narration}], short_history (bool: true when the salary rests on the under-3-months no-keyword rule - a company paying an exact, non-round amount (not a multiple of 500) on a fixed pay day in every pay month of a 1.8+ month statement, no rent/SWP/fee/retainer/household/commission/reimbursement remark, not taken back by a lender mandate; raises SALARY_SHORT_HISTORY), candidates: [{name, score, months, avg_amount}]` |
| `loans` | obj | `emis: [{lender, amount, occurrences, months, first_date, last_date, mechanism, active, returned, variable?, kind: fixed|short_term, basis}]`, `monthly_obligation` (active fixed EMIs only), `short_term_repayments: {monthly, lenders}` (active short-term / payday repayments: varying amounts, 2 hits, or a lender that also lent in the statement), `disbursals: [{date, lender, amount, narration}]`, `oneoff_repayments: [{date, lender, amount, narration}]`, `credit_card: {count, total}`, `distinct_lenders: [str]` |
| `bounces` | obj | `count, charges_count, events: [{date, narration, amount, type: bounce\|charge}], months_with_bounce: [str]` |
| `top_credits`, `top_debits` | list | top 10 `{date, narration, amount, counterparty, category}` |
| `monthly` | list | `{month, credits_count, credits, debits_count, debits, net, opening, closing, abb, min_eod, max_eod, salary, emi, bounces, cash_deposits, cash_withdrawals}` |
| `categories` | obj | `credits: [{category, count, amount}], debits: [...]` sorted by amount desc |
| `counterparties` | obj | `top_payers: [{name, count, amount}], top_payees: [...]` (top 10) |
| `cash` | obj | `deposits_count, deposits_amount, withdrawals_count, withdrawals_amount` |
| `risk_flags` | list | `{severity: high\|medium\|low, code, message}`. `STATEMENT_TRUNCATED` (high): rows end before the header period (see `meta.truncated`) - the missing tail is unseen, get it from the bank. `SALARY_SHORT_HISTORY` (medium): "Salary seen in only N months - verify with payslips" - the salary has no salary keyword and rests on 2 pay months of a statement under 3 months (`salary.short_history`); confirm with payslips before using it |
| `upi_mobiles` | obj | UPI payments to / from a mobile-number UPI ID (Excel sheet 'UPI Mobiles'; `bsa/engine/upi_contacts.py`): `count` (phones), `txn_count, paid_count, paid_total, received_count, received_total`; `contacts: [{mobile, name, upi_apps, paid_count, paid, received_count, received, net (received - paid), txn_count, months, first_date, last_date, unverified, own_account}]` (largest paid+received first); `transactions: [{idx, date, mobile, upi_id, source, direction: Paid\|Received, amount, balance, name, narration, verified, note}]` grouped by contact. Mobile = 10 digits 6-9 as the UPI ID's name part before '@' (PhonePe '-2', 91 prefix, wrapped lines in Indian/RBL/ICICI or confirmed elsewhere), SBI's handle-less payee field ('/YESB/<mobile>/'), YES 'From:/To:' picks the counterparty side; never an account-number UPI ID / e-mail / merchant code; the holder's own number (a/c = mobile) is skipped. Older saved reports lack it - the Excel export rebuilds it from `transactions` |
| `transactions` | list | `{idx, date, value_date, narration, debit, credit, balance, category, counterparty, verified (bool), tags: [str]}` (debit/credit: float or 0) |
| `warnings` | list[str] | parse/coverage warnings (incl. 'Statement truncated by bank export limit: rows end .., header says ..') |
| `data_quality` | obj | underwriting gate: `level`: `READY` (every row reconciles, closing matches) \| `REVIEW` (>=98% rows reconcile; human must check the mismatch rows) \| `NOT_USABLE` (<98%, or verify-only); `underwriting_ready` (bool, true only for READY), `unverified_rows`, `unverified_amount`, `message`. Also raised as risk flag `DATA_NOT_VERIFIED` (high) / `DATA_REVIEW` (medium). |
